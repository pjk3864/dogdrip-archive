OCI = Oracle Cloud Infrastructure, AWS = Amazon Web Services예요. 둘 다 클라우드인데 방향성이 꽤 다릅니다.

 

항목 OCI AWS

성격 고성능 인프라 + Oracle 생태계 특화 뭐든 다 있는 종합 클라우드

서비스 수 비교적 적고 핵심 위주 미친 듯이 많음

가격 대체로 단순하고 공격적 복잡하고 경우에 따라 비쌈

네트워크 비용 특히 외부 전송 비용이 상대적으로 관대한 편 데이터 나가면 비용이 꽤 붙는 편

VM 성능/가격 CPU/RAM 구성 자유도가 좋음 인스턴스 종류 엄청 많음

Oracle DB 압도적 강점 가능하지만 OCI가 본진

서버리스/AI/관리형 서비스 충분하지만 AWS보다 선택폭 좁음 Lambda, DynamoDB, SageMaker 등 엄청 방대

글로벌 생태계 상대적으로 작음 업계 표준급

문서/커뮤니티 조금 답답할 때 있음 자료가 넘쳐남

기업 취업/범용성 Oracle 쓰는 회사에서 강함 거의 어디서든 통함

 

핵심 차이는 이거예요.

 

AWS

 

AWS는 약간 “클라우드판 대형마트”예요.

 

EC2로 서버 만들고,

S3에 파일 넣고,

RDS로 DB 돌리고,

Lambda로 서버리스 만들고,

CloudFront CDN 붙이고,

Route53 DNS 쓰고,

SQS 큐 만들고,

EKS로 Kubernetes 돌리고…

 

진짜 웬만한 기능은 AWS 안에 다 있습니다.

 

그래서 서비스 하나 만들다가

 

“아 이것도 필요하네?”

 

하면 거의 항상 AWS에 이미 뭔가 있어요. ㅋㅋㅋ

 

대신 단점도 정확히 거기서 나옵니다.

 

너무 많아요.

 

서비스 이름도 처음 보면 암호 수준이고,

 

EC2 + EBS + ALB + NAT Gateway + VPC + IAM + CloudWatch + Route53...

 

이러다 보면

“나는 웹서버 하나 만들려고 했는데 왜 네트워크 엔지니어가 되어 있지?”

상태가 됩니다. ㅋㅋㅋ

 

그리고 AWS는 비용 구조가 상당히 복잡한 편이에요. 특히 트래픽 많이 나가면 예상치 못한 비용이 생기기 쉽습니다.

 

OCI

 

OCI는 반대로

 

“우리가 AWS보다 늦게 시작했으니 인프라 가격이랑 성능으로 때려보자.”

 

느낌이 꽤 강합니다.

 

특히

 

Compute / RAM / Network / Oracle DB

 

쪽이 강해요.

 

예를 들어 서버 하나 만들 때 OCI는 CPU랑 RAM을 비교적 유연하게 지정할 수 있는 구성이 있어서,

 

CPU 4코어

RAM 24GB

 

같은 애매한 조합도 만들기 편합니다.

 

AWS는 보통

 

이 인스턴스는 4코어 16GB

그다음은 8코어 32GB

 

같이 정해진 인스턴스 타입을 골라야 하는 경우가 많죠.

 

그래서 단순 VM 서버만 돌리는 사람에게는 OCI가 꽤 매력적일 수 있어요.

 

그리고 OCI의 진짜 본체는 역시

 

Oracle Database

 

입니다.

 

기업이 이미

 

Oracle DB

ERP

Java Enterprise

Exadata

 

같은 걸 쓰고 있다면 OCI로 옮기는 게 굉장히 자연스러워요.

 

특히 Autonomous Database / Exadata Cloud 쪽은 Oracle이 자기 DB를 자기 클라우드에서 돌리는 거라 최적화 수준이 다릅니다.

 

쉽게 말하면

 

AWS가 클라우드의 스위스 아미 나이프라면

OCI는 Oracle DB를 등에 업은 고성능 서버 전문점에 가까워요.

 

이런 거 만들면 AWS

 

게임 백엔드, 웹서비스, SaaS, 대규모 API, 서버리스, 글로벌 서비스, 여러 관리형 서비스를 조합하는 프로젝트.

 

특히

 

게임 서버

├─ API Gateway

├─ Lambda

├─ DynamoDB

├─ S3

├─ CloudFront

├─ Cognito

└─ CloudWatch

 

이런 구조 만들 거면 AWS가 엄청 편합니다.

 

서비스끼리 레고처럼 붙일 수 있어요.

 

이런 거면 OCI도 엄청 좋음

Linux 서버 하나

Python 서버

Docker

Database

Discord Bot

웹사이트

게임 전용 서버

렌더 서버

VPN

개인 서버

 

처럼 VM 중심으로 굴리면 OCI가 상당히 매력적입니다.

 

괜히 AWS 서비스 8개 조합할 필요 없이

 

“서버 하나 주고 IP 하나 주세요.”

 

하고 직접 구축하면 되니까요.

 

그리고 꽤 웃긴 특징 하나가 있습니다.

 

OCI는 한동안 개발자들 사이에서

 

“Oracle인데 무료 서버가 이상하게 혜자다.”

 

로 유명했어요. ㅋㅋㅋ

 

Oracle이라는 회사 이미지 때문에 경계하는 사람들도 있는데, 클라우드 VM 자체는 가격 대비 성능을 상당히 공격적으로 밀어붙이는 전략을 써왔습니다.

 

반대로 AWS는

 

“싸서 쓴다”

 

라기보다는

 

“생태계가 너무 커서 쓴다.”

 

쪽입니다.

 

그래서 정말 짧게 요약하면:

 

AWS: 돈 조금 더 내더라도 온갖 기능과 생태계를 쓰고 싶다.

OCI: 서버/DB 성능과 비용 효율이 중요하고, 특히 Oracle을 쓴다.

 

그리고 개인 개발자 입장에서 제가 좀 더 극단적으로 표현하면:

 

AWS = 클라우드를 이용해서 프로그램을 만든다.

 

OCI = 클라우드에서 컴퓨터를 빌린다.

 

이 차이가 제일 감각적으로 이해하기 쉬워요. ㅋㅋㅋ
